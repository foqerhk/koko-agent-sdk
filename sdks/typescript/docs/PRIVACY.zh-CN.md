# 本地隐私步骤与可见目标

## 1.2.2 行业敏感步骤

进入接管等待时，SDK 在宿主上方显示常驻提示，说明需要用户完成的操作，并短震动
一次。提示可以收起再展开，不覆盖全屏触控；聊天面板也保留接管说明和返回应用的
入口。只有新的接管步骤才再次震动，状态轮询与重复检测不会反复提醒。震动遵循
设备设置，模拟器不能代表真实手感；Android 原生包需合并 SDK 的 VIBRATE 权限。
旧原生包未声明该普通权限时跳过震动，提示与等待流程仍可使用。

“我已完成，继续检测”只请求本机重新检查，不会清除宿主 gate，也不能绕过敏感页。

导入助记词前的安全声明页同样需要本人操作：结合安全检查标题、所有权/来源/风险
声明及确认控件识别，即使 Continue 尚未启用或原生树未暴露按钮/复选框属性也暂停。
属性缺失时要求所有权、来源、泄露风险三类声明和明确的确认文案同时出现。
用户应逐项核对，仅在声明属实时勾选；启用 Continue 本身不会解除接管，必须离开
确认页并重新核验。普通教育文章和导入菜单不因出现助记词字样而触发此声明规则。

助记词、种子/恢复短语与私钥同级。展示、输入、导入和验证页，以及 Keystore、
API 密钥、恢复码、银行卡资料、身份资料输入/验证页，必须在本地拦截页面上传、
OCR 和截图；私密值不得出现在任务、无障碍标签、标记或日志里。

Web3 的消息/交易/类型化数据签名、代币额度/Permit/NFT 全局授权，以及兑换、
跨链、质押、支付/提现、自动扣款和账号恢复/删除等实际确认步骤交由用户完成。
普通导航入口、查询和教育说明不因出现相关词语而一律暂停。任务开始前确认或
`confirmation.mode: 'off'` 不能绕过已识别的本地敏感步骤。

宿主可显式声明 `web3_signature`、`web3_authorization`、`financial_transaction`、
`account_change`、`account_secret`、`financial_data`、`identity_data` 等 gate。
例如在签名请求显示前调用 `setAppUserGate({ kind: 'web3_signature', label: '请在钱包中核对并签名' })`，
实际请求消失后再调用 `clearAppUserGate()`。SDK 不拦截任意 dApp RPC，也无法仅凭
通用标题识别所有自绘/WebView 页面；关键业务仍应绑定宿主的实际请求状态。

云端 `ask_user` 请求的普通选择页不会仅因经过 1.5 秒而继续。用户应先完成选择、
离开该页再点继续；若进入已识别的敏感步骤，离开后重新核验安全页面。点击继续
不能绕过仍在显示的敏感请求，空白转场也不能证明操作已完成。

账户恢复凭证、私密认证数据和密码的展示、备份、验证或导入，必须由用户在宿主内完成。SDK 在这些页面暂停任务，不代选敏感验证项、不代填密码，也不把页面树、OCR、页面摘要或截图发送给模型。离开隐私页后才恢复；点击“已完成”不能绕过仍在展示的隐私页。

宿主应为敏感内容容器加固定标记，例如 `testID="privacy-sensitive-recovery"` 或 `testID="privacy-sensitive-secret"`。不要把实际恢复数据、私密认证材料或密码拼进 `testID`、无障碍标签或日志。密码输入框应启用 `secureTextEntry`。这些标记应覆盖导入、展示与验证的所有状态。

对于原生树不能可靠识别的页面，宿主应在页面聚焦时调用 `setAppUserGate`，使用不含秘密的通用提示，例如“请在本机完成敏感恢复步骤”，离开后调用 `clearAppUserGate()`。在页面内容出现前设置，在内容移除后清除，避免后台仍挂载的路由干扰当前页。页面标题启发式识别只是兜底，不能替代宿主显式标记。

发送层重新检查当前原生页面，丢弃调用方传入的原始 OCR、摘要和截图字段，从同一份脱敏树生成上传内容。进入隐私步骤时清空规划历史；网关也拒绝已识别的隐私页。调试时仅使用虚构数据验证请求拦截，不用真实秘密测试脱敏。

点击只针对当前可见目标。目标缺失时，SDK 只在原生确认可纵向滚动的容器内执行可见滑动，每次重新读取页面，找到目标后才单次点击。列表不再变化或达到搜索上限时停止并报告未找到，避免连续猜点。
